# **Introducción** 

## **De las herramientas integradas a las herramientas del ecosistema** 

### **Tu recorrido:** 

- **Parte 1:** Comprendiste las herramientas a nivel fundamental y creaste tu primer agente habilitado para herramientas. 

- **Parte 2:** Utilizaste las herramientas integradas listas para producción que proporcionó el ADK. 

- **Parte 3:** Te conectas a servidores de herramientas externos a través de un protocolo estandarizado. 

**El cambio:** En lugar de utilizar herramientas integradas en el ADK, te conectas a servidores de herramientas preexistentes que la comunidad y el ecosistema se encargan de mantener. 

# **El problema** 

## **Capacidades que van más allá de lo integrado** 

En el módulo 2, aprendiste que las herramientas integradas ahorran tiempo en comparación con la escritura de integraciones personalizadas. Pero, qué pasa con las siguientes capacidades: 

- # Necesitas capacidades como: 

- # - Acceso al sistema de archivos 

- # - Conexiones de base de datos 

- # - Integraciones de API de terceros (Slack, Notion, GitHub) 

- # - Herramientas especializadas para dominios específicos 

- # ¡Estas no están integradas en ADK! 

- # ¿Tienes que escribir todo por tu cuenta? 

### **Problemas con la creación de todo desde cero:** 

- ❌ **No están integradas en el ADK** : muchas funciones útiles no están incluidas como herramientas integradas. 

- ❌ **Ya existen como herramientas de código abierto** : alguien más ya ha resuelto estos problemas. 

- ❌ **Requieren una implementación compleja** : las integraciones reales necesitan protocolos, autenticación y manejo de errores. 

- ❌ **Los expertos se encargan del mantenimiento** : conocimientos específicos de la herramienta que no necesitas aprender. 

**El problema raíz:** Existe un enorme ecosistema de herramientas prediseñadas, pero ¿cómo las conectas a tu agente del ADK?
